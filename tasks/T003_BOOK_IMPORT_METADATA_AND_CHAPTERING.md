# T003：实现元数据识别与空行分章导入链路

## 目标

把当前单一文件名模板扩展为可维护的元数据规则体系，并增加全局“空行分章”，同时保持 NovelSpeaker 选择 TXT 后直接导入的轻量流程。

## 权威参考

- `docs/specs/BOOK_IMPORT.md`
- `docs/05_DATA_AND_COMPATIBILITY.md`
- `docs/06_UI_AND_VISUAL_SYSTEM.md`
- `docs/03_BOOKS_PLAYBACK_AND_PROGRESS.md`
- `AGENTS.md`

## 0. 持久化授权检查点

开始时只读审计当前 Book/Rule/Settings 持久化。预计至少检查以下独立变更：

1. Book Description 的持久化字段；
2. 文件名元数据规则的持久化；
3. 正文头部元数据规则的持久化；
4. 全局“空行分章”设置的持久化。

对每一项真实需要的数据库结构或持久数据变更，按照 `AGENTS.md` 单独向用户说明：变更对象、原因、数据影响、升级/回退与旧数据保留方案。未获该项明确批准前不得修改 migration/schema/settings migration，也不得通过旁路存储规避授权要求。

如果全部相关持久化已经由现有通用结构承载且无需数据格式变更，应记录证据后继续。

## 1. 导入管线

实现 `BOOK_IMPORT.md` 的稳定顺序：

```text
选择 TXT
→ 编码/规范化
→ 用章节规则寻找显式章节标题
→ 文件名元数据规则
→ 正文头部元数据规则
→ 章节规则 + 可选空行分章
→ name 文件名回退
→ 持久化
```

保持：无编码问题时选择文件后直接完成导入，不增加 per-book wizard。

## 2. 元数据规则

新增两个独立规则类型/工作台，不建立 SourceType 万能模型：

- FileNameMetadataRule：第一条有效命中胜出，之后停止；多个文件名规则之间不合并字段。
- TextHeaderMetadataRule：按序执行，先得到字段优先，后续只补缺失字段。

共同要求：

- .NET Regex named captures：`name`、`author`、`description`；
- 至少一个受支持字段必须存在；其它 named group 可以存在但不写元数据；
- Regex 保存前校验；
- 无测试输入区；
- 提供保守通用默认规则，不出现 Legado 专属设置/命名。

旧 `BookFileNameTemplate` 与 parser 直接删除，不迁移旧模板、不保留兼容 alias。

## 3. 正文头部范围

- 先用章节规则确定第一个显式章节标题；空行分章不得参与头部边界。
- 有显式标题时扫描其之前全部头部内容，包括空行。
- 无显式标题时只扫描实现确定的有限前缀，不扫描全文。
- 元数据提取只读，不从正文删除匹配行。

## 4. 空行分章

- 新增长期全局开关，位于设置“导入 → 章节识别”。
- 与章节规则同时生效；显式章节标题优先。
- 标题后、首行正文前的空行不额外分章。
- 正文后的空行是候选边界；若下一个非空行是显式章节标题，则吸收空行边界。
- 连续多个空行视为一个边界；首尾空行不创建空章节。
- 无显式章节标题：关闭时保持“全文”，开启时按空行切章。
- 空行生成的无标题章节使用最终 catalog 1-based 位置命名“第 N 节”。
- 不改变 TextSegmenter 当前“每一个非空行是一个自然段”的逻辑。

## 5. Settings IA 与详情页

按 `06_UI_AND_VISUAL_SYSTEM.md` 调整：

- 设置首页分组改为“导入与文本”；
- 顶层只有“导入”和“正则替换”；
- “导入”页承载长段拆分、两个元数据规则入口、空行分章、章节规则入口；
- 书籍详情展示 Description（存在时）；
- 不增加导入向导。

## 不要做

- 不修改用户源 TXT。
- 不自动把规则变化应用到已导入书籍。
- 不增加 Legado mode/兼容入口。
- 不提前设计 EPUB/在线书源通用 metadata framework。
- 不把导入元数据规则与运行时 RegexReplacement 合并。

## 核心测试

至少保护：

- 文件名首个有效命中停止；
- 文件名字段优先于正文头部；正文规则只补缺失字段；
- 元数据与第一章之间有空行时不创建额外章节；
- `正文 + 空行 + 显式下一章标题` 只产生两个章节；
- 标题后空行不拆出空章节；
- 无显式标题时开关 ON/OFF 语义；
- 自动“第 N 节”使用最终目录位置；
- 元数据识别不修改正文；
- name 最终回退源文件名；
- 无编码问题仍可直接导入。

阶段完成前执行完整质量门禁。
