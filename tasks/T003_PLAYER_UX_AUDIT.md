# T003 — 播放页正文跟读、滚动与反馈的定向审查

**优先级：P1 / 定向审查，条件性最小修复。** 依赖：T001、T002。此任务不授权全面重新设计 UI。

## 1. 为什么需要此任务

U2 除布局外，仍需要确认目前已建立的核心播放交互能否在新尺寸与分隔宽度下保持清晰、稳定。当前项目已有 `PlayerAutoScrollCoordinator`、`PlayerScrollInteractionController`、`PlayerInteractionController`、`PlayerViewModel`、`PlayerPlaybackProjection` 与 XAML 的 InlineLoading/PlaybackError 等状态。优先检查**真实可见问题**，不要因类多或 UX 主观偏好就重构这些组件。

## 2. 检查矩阵与既有合同

1. **正文跟读与定位**：当前朗读段视觉突出，非当前段有适当上下文；自动推进时居中动画可靠，明确手动滚动/滚动条拖动时暂停自动定位，“返回当前段落”恢复；显式跳段/跳章有正确的视觉定位。宽度改变导致文本重新换行时，视觉定位不能漂移到错误段落。
2. **准备、等待与失败**：UI 先提交 logical target 并显示目标章节和段落，再异步等音频；真实等待时显示轻量准备/重新生成提示；失败不回滚阅读位置，Retry 和切 Provider 仍可触达。不得新增导致连续闪烁、阻断导航的大范围遮罩。
3. **状态与控件**：播放/暂停及段落 Slider，前后段/章节边界可用性，定时停止与剩余时间、音量、语速、Provider 浮层关闭/ESC 及焦点行为；不随意改掉既有用户熟悉的核心位置或设定语义。
4. **布局交叉条件**：小/大窗口高度，默认/极端双栏宽度，长章节名/长段落、空章节、无可用 Provider、播放出错、章节多选与主动缓存状态、Light/Dark；检查 Header/Footer 抢占高度、浮层双背景/直角残影、段落文本裁切和滚动条遮挡。
5. **性能/生命周期**：目录至少保持 10k 虚拟化；页面离开/返回不会造成重复订阅、重复动画或 stale UI；仅当发现可复现问题时调查性能，避免另开 E2 全面 profiling。

## 3. 交付与修复权限

- 先逐项给出 `符合 / 明确问题（复现步骤+代码证据） / 环境无法验证`，形成项目根目录临时 `U2_PLAYER_UX_AUDIT.md`，不加入 Git 或提交。使用 `.git/info/exclude` 或仅确保未暂存；不要为临时报告创建正式 docs。
- 有**用户可见、可以重复验证**的 P0/P1 交互缺陷，且修复不改变已确定交互模型或超出 Player 所有权时，在本任务中做最小修复并记录回归验证。
- 仅属审美选择、没有事实支撑的“可能更漂亮”、新增面板/按钮、音频业务逻辑调整、复杂交互重构，**不实施**；可以记录为下一轮候选，不能当作 T003 必做项。
- 如果没有发现可靠的问题，报告“未发现足以实施的缺陷”，不需要为了完成任务修改源码或加测试。
- 允许隔离 WPF 截图与少量临时测试，仅用虚构内容，不读取真实用户书籍/音频；临时资源测试后删除。若无安全 GUI 环境，明确标记对应视觉条目 `未验证`，不能捏造验收通过。

## 4. 自动验收与关闭

- 对实际修改执行相关 focused tests、Release build、format/diff/LF；对纯审查任务不强制完整 build/test。
- 不改变 Playback Session/Speech/Cache/ActiveCache 的内部合同，不引入新的状态源或通用 UI framework。
- Backlog 记录发现的问题、是否修复、未验证的边界；删除任务规格。审查报告属于用户手动管理的根目录临时文件，不纳入 Git。
