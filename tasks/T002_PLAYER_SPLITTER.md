# T002 — 播放页双栏可拖动分隔条与目录宽度偏好

**优先级：P1 / 实现任务。** 依赖：T001 垂直 viewport 修复。

## 1. 已批准产品设计

保留左目录/右正文常显的双栏，不做自适应单栏或自动隐藏目录。当前 `PlayerView.xaml` 内容区为 `320 / 24 / *` 三列，计划在现有中间间距中加入原生 WPF `GridSplitter` 或等价成熟标准控件。

- 默认目录**偏好宽度** 320 DIP；正文总是占用余下的可用宽度。
- 拖动手柄左右或通过键盘改变目录宽度；鼠标进入变水平 resize cursor、轻量 hover/focus 反馈；平时仅一条低存在感的竖向指示线。中间空隙依旧约 24 DIP，视觉手柄不应像实体按钮或额外 Card。
- 建议目录最小 220 DIP、正文最小约 360 DIP。以实际 Shell/导航栏展开和 `MainWindow.MinWidth=900` 时的 viewport 实测为准，合理微调数值以**确保窗口最小尺寸下也能布局**；目录与正文不能被拖到不可用。空间充裕时无必要对目录设置特别低的最大值以限制用户；它的实际最大值由正文最小宽度决定。
- 窗口**横向拉宽/拉窄时不保持两列比例**：默认保持用户指定目录宽度，正文吸收剩余宽度变化。
- 当可用宽度不足以同时容纳偏好目录宽度、正文最低宽度及分隔区时，目录的**实际宽度可临时缩小**；窗口再次加宽后应恢复原来的目录**偏好宽度**。自动收缩不是一次新的用户拖动，不得覆盖偏好。
- 只保存每个用户一份简单宽度偏好，跨页面/重启可恢复；不做 per-Book 宽度、窗口尺寸记忆表或新的数据库持久化。沿用当前设置存储的增量可选字段、默认值/Normalize 流程；老设置文件可直接按默认值加载，不需迁移。

## 2. 技术实施边界

1. 优先复用 WPF `GridSplitter` 的相邻 Grid 列 resize、键盘和焦点能力，不造自定义鼠标 capture/drag manager。可能需要少量 Player View 级代码以分离 `PreferredCatalogWidth` 与 `EffectiveCatalogWidth`，但不引入通用 layout service。
2. 需要显式区分 **用户发起的拖动/键盘调整** 与 **窗口、导航栏大小改变导致的临时宽度变化**；只有前者改变持久偏好。窗口大小连续变化、页面再进入、窗口恢复时不能产生宽度漂移。
3. 在最小 `MainWindow` 宽度、侧边栏打开与收起、Provider/章名较长、章节管理工具显示等情况下，不增加全局水平滚动、不导致正文标题和关键控件溢出。保留原 XAML Virtualization、列表选择、上下文菜单、自动滚动等功能。
4. 分隔手柄实际可点击/拖动区域应比竖线视觉本身稍宽，触控板/鼠标容易命中；避免覆盖章节/正文点击；提供键盘 focus visible / AutomationProperties.Name 与稳定的水平 resize 意义。
5. 配色只用现有 UI token / DynamicResource，Light/Dark/高对比焦点可读；不编写整套 GridSplitter 模板或 Wpf.Ui 控件替代实现。持久化采用低频 commit（例如 drag completed/用户键盘调整后），不要鼠标每移动一像素写 settings.json。

## 3. 验证

- 默认首次进入目录约 320 DIP；鼠标改变宽度后正文自然变化；键盘可调整，限界有效。
- 两个方向调整窗口宽度（包含最窄情况）时，目录尽量保留偏好，空间不足时有效宽度临时变化、恢复宽度后能恢复先前偏好。再次打开 Player/应用可恢复偏好。
- 重复拖动、最小宽度/最大宽度 clamp、NavigationView 展开/收起不出现异常 Resize 循环、UI 卡顿、水平页面溢出或保存值错误。
- Light/Dark、hover/focus、章节/段落点击、章节缓存百分比、滚动、虚拟化和 T001 的纵向伸缩不回归。
- 只添加能保护核心布局可用性/持久偏好语义的少量正式行为测试；drag hit-test、样式和像素效果用临时隔离 WPF 验收。完成时 focused tests + Release build、format/diff/LF 检查。
