## Epic W：书库美化与直接导入调整

- [x] **LIB2-001：重做书库页视觉层级。** 去掉覆盖整页的大面积外层容器，改为“顶部工具栏 + 响应式书架网格”；标题、搜索框、排序菜单和导入按钮在顶部对齐；标题下方显示轻量摘要；卡片区域使用内部滚动。
- [x] **LIB2-002：美化横向书籍卡片。** 保持封面在左、信息在右的横向卡片；优化封面比例、信息层级、卡片圆角、描边、悬停态、焦点态、进度条和长文本省略；不增加“正在阅读 / 未开始 / 已读完”状态标签。
- [x] **LIB2-003：调整书库搜索清空交互。** 移除独立“清空”按钮，改为搜索框内部清空图标；搜索无结果时显示页内空状态并提供清空入口。
- [x] **LIB2-004：移除导入预览流程。** 选择或拖入 TXT 后直接检测编码、解析章节并写入正式数据；不再显示正文预览、章节预览、重新预览或确认导入步骤。
- [x] **LIB2-005：实现低置信度编码最小对话框。** 仅在自动编码检测低置信度或失败时弹出最小编码选择对话框；用户选择编码后继续直接导入。
- [x] **LIB2-006：调整导入进度与重复书籍处理。** 小文件使用轻量进度提示；大文件显示可取消进度对话框；重复书籍直接拒绝导入并提示“该小说已经导入”。
- [x] **LIB2-007：清理旧导入 UI 和死代码。** 删除或停用 `ImportBookDialog` 中正文预览、重新预览、确认导入等不再使用的 UI 和 ViewModel 状态；保留必要的进度、取消和编码选择能力。
- [x] **LIB2-008：补齐书库与导入测试。** 覆盖直接导入成功、编码低置信度、编码选择取消、重复书籍拒绝、大文件进度取消、导入失败不污染书库、搜索清空图标和横向卡片可访问性。

### Epic W 验收

- 书库视觉上不再出现只有少量书籍时的大面积空容器。
- 搜索框清空是内嵌图标，不再有独立清空按钮。
- 常见编码 TXT 可在选择后直接导入并出现在书架。
- 编码不确定时只要求选择编码，不显示正文预览。
- 重复书籍不会生成副本，也不会覆盖原书。

## Epic Y：章节规则启用 / 排序与编辑副本解耦

- [x] **CHRULE2-001：移除右侧启用字段。** 章节规则右侧编辑区只保留名称、正则表达式、正则校验提示、删除、取消和保存；不显示启用开关，也不显示只读启用状态。
- [x] **CHRULE2-002：左侧启用即时保存字段化。** 左侧启用 / 禁用直接保存持久化对象的启用字段；当前正在右侧编辑的规则也允许左侧启用 / 禁用；失败时只回滚开关状态。
- [x] **CHRULE2-003：左侧排序即时保存字段化。** 拖拽排序和上移 / 下移直接保存排序字段；失败时回滚顺序或重新加载；不影响右侧名称和正则表达式编辑副本。
- [x] **CHRULE2-004：右侧保存改为字段级更新。** 右侧保存时基于最新持久化对象，只写入名称和正则表达式，不覆盖左侧已经保存的启用状态和排序。
- [x] **CHRULE2-005：调整未保存修改保护。** 切换规则、返回、新建、导入默认、恢复默认、删除或关闭页面前保护右侧名称 / 正则修改；左侧启用 / 禁用和排序不因右侧未保存修改而被阻止。
- [x] **CHRULE2-006：补齐章节规则测试。** 覆盖当前编辑项启用切换、排序后保存右侧副本不覆盖排序、启用失败回滚、排序失败回滚、右侧取消不回滚左侧已保存状态、未保存保护不拦截左侧即时操作。

### Epic Y 验收

- 当前打开的章节规则可以在左侧启用 / 禁用和移动排序。
- 右侧保存名称或正则表达式不会覆盖左侧刚刚保存的启用状态或排序。
- 右侧编辑区不再出现启用字段。

## 发布候选通过条件

以下条件同时满足时，才可认为新版 UI 达到发布候选：

- 当前 backlog 中阻塞级任务已关闭，非阻塞项已明确写入已知限制。
- `06_UI_AND_USER_FLOWS.md`、`06A_SETTINGS_PAGES.md`、产品范围、决策文档和实际实现一致。
- 书库、TTS 规则、章节规则中不存在 `DataGrid`。
- 书库使用优化后的横向书籍卡片网格，常见编码 TXT 可直接导入。
- 书籍详情页全局不滚动，章节目录虚拟化，并支持章节跳转播放。
- 播放页自动切段和主动跳转居中有平滑动画，手动浏览不会被抢滚动。
- 章节规则左侧启用 / 排序与右侧名称 / 正则编辑完全解耦。
- 一级导航只有书库和设置，底部全局播放器条已删除。
- 从首次启动、导入小说、导入并试听规则、播放、跳章/跳段、返回书库继续播放、切换书籍、重启恢复均可仅通过 UI 完成。
- 浅色、深色、跟随系统在 Windows 10/11 均通过验收。
- `dotnet format --verify-no-changes`、`dotnet build -c Release`、`dotnet test -c Release` 全部通过。
- 至少使用三本不同编码/章节结构的 TXT 和三个不同结构的 HTTP TTS 规则完成端到端验收。
- 日志、规则导入/编辑、试听和错误界面均未泄露正文或凭据。
