# 发布版任务清单

本清单供 AI Agent 按顺序领取任务。每个任务应尽量独立、可测试、可提交。

本清单的目标是推动项目达到“任务完成后可形成较完整、可发布候选版本”的范围。也就是说，当未完成项基本清零时，预期应得到：

- 可由普通用户独立完成导入 TXT、导入规则、测试规则、开始播放、恢复进度和清理缓存。
- 对常见失败场景有明确反馈和可执行恢复路径，而不是只显示技术错误。
- UI、设置、凭据、缓存、日志、文档和打包均达到发布候选质量，而不只是开发演示状态。

除非另有说明，每个 Epic 收尾时都应补齐：

- 自动化测试。
- 必要的 UI/交互文档更新。
- 最低手动验收步骤。
- 已知限制记录。

## 发布候选通过条件

以下条件同时满足时，才应认为本清单已经把产品从 demo 推进到可发布候选：

- 所有未完成任务均已关闭或明确降级到“已知限制”。
- `docs/06_UI_AND_USER_FLOWS.md`、产品范围和已知限制与实现一致。
- `dotnet format --verify-no-changes`、`dotnet build -c Release`、`dotnet test -c Release` 全部通过。
- 至少使用三本不同编码/章节结构的 TXT 和三个结构不同的 HTTP TTS 规则完成端到端验收。
- 从首次启动、导入、规则测试、连续播放、切章、切规则、断网恢复到重启恢复的全流程都可由 UI 独立完成。
