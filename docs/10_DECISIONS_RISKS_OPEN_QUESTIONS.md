# 决策、风险与待定问题

## 已确定决策

### 平台和 UI

- Windows 10/11。
- C#、.NET 10、WPF。
- 第一版 x64。
- CommunityToolkit.Mvvm。

### 文件格式

- 第一版只支持 TXT。
- EPUB 等格式推迟。

### 在线 TTS

- 核心为 Legado 风格 HTTP TTS 规则。
- 不绑定固定云服务商。
- 第一版不需要自建后端。
- 用户自行提供可用规则及其凭据。
- 完整段落音频下载后再播放。
- 不实现 WebSocket 和真正流式播放。
- 第一版承诺的是“常见 HTTP TTS 规则兼容子集”，而不是兼容所有社区规则。
- 第一版支持会话内 Cookie，不支持 Cookie 持久化。
- LoginInfo 作为只读输入参与规则求值。
- 第一版不包含 Windows 本地 TTS 回退。

### 播放和缓存

- NAudio。
- 默认预取后续两个段落。
- 缓存默认上限 2 GB。
- 缓存按规则、语速和文本区分。
- 跳转和配置变化创建新播放会话。

### 数据

- SQLite 保存书籍、章节、进度、规则和缓存索引。
- JSON 保存非敏感设置。
- DPAPI 或 Credential Manager 保存敏感信息。

## 主要风险

### 1. Legado 规则兼容度不明确

风险：

- 社区规则可能依赖复杂 `java`、`source`、Cookie 或登录脚本。
- 一些规则可能依赖 Rhino 特性。
- 不同规则的 URL 附加配置格式可能存在边缘情况。

缓解：

- 明确发布兼容矩阵。
- 第一版只承诺常见 GET/POST 规则。
- 导入时显示不支持字段。
- 建立真实规则样本测试集。
- 解析和脚本层独立封装。

### 2. 不可信 JavaScript

风险：

- 无限循环。
- 资源消耗。
- 访问系统能力。
- 凭据泄露。

缓解：

- Jint 白名单环境。
- 禁止 CLR。
- 设置执行限制。
- 每条规则隔离。
- 日志脱敏。
- 不提供通用网络和文件 API。

### 3. 在线服务差异

风险：

- Content-Type 不准确。
- 返回 JSON 但状态为 200。
- 音频格式不统一。
- 限流语义不同。
- Token 频繁过期。

缓解：

- 响应验证。
- 音频解码验证。
- 可配置 Content-Type。
- 规则级限流。
- 清晰错误分类。
- 登录信息独立更新。

### 4. 播放状态竞争

风险：

- 用户快速切章。
- 旧请求晚到。
- 预取和当前段重复请求。
- 多个完成事件同时推进。

缓解：

- `PlaybackSessionId`。
- CancellationToken。
- 单一协调器。
- 状态变更串行化。
- In-flight 请求去重。
- 大量状态机测试。

### 5. TXT 格式混乱

风险：

- 编码误判。
- 章节规则误判。
- 超大文件。
- 无换行文本。

缓解：

- 编码预览。
- 多级回退。
- 无章节回退。
- 长段强制切分。
- 导入过程后台执行。
- 保留原始文件。

### 6. GPL 许可证

参考项目使用 GPL 类许可证。直接复制其代码可能带来开源义务。

缓解：

- 只参考公开行为、字段和交互思想。
- 独立编写 C# 实现。
- 不直接翻译或复制 Kotlin 源文件。
- 保存设计决策记录。
- 发布前进行许可证审查。

## 已知限制（第一版）

- 不保证兼容所有社区规则。
- 不支持 WebView 登录相关规则。
- 不支持 `jsLib`。
- 不支持复杂 `source.get/put` 可变状态语义。
- 不支持 Cookie 持久化。
- 不支持真正的流式边生成边播放。
- 不包含 Windows 本地 TTS 回退。

## 默认实现决策

为了避免阻塞开发，第一版直接采用：

- 暂停时最多继续预取 1 个段落。
- 当前段最终失败后暂停，用户选择重试或跳过。
- 保存段内音频时间。
- 第一版重点支持 MP3 和 WAV。
- 规则没有 Content-Type 时尝试按文件头和解码结果识别。
- 删除书籍默认不删除缓存，由用户显式选择是否清理。
- 单本书专属规则和语速推迟到第二阶段。
- 发布形式先使用自包含便携 ZIP。

## 剩余待定问题

- 应用正式名称。
- `Header` 字段编辑体验以 JSON 为主、文本为辅，还是仅保留一种输入形式。
