# 开发里程碑

## 总体策略

按可运行的纵向切片推进，而不是先实现所有基础设施。

每个里程碑都应包含：

- 可运行程序。
- 自动测试。
- 手动验收步骤。
- 已知限制。
- 必要的文档更新。

---

## M0：仓库和工程骨架

### 目标

建立可持续开发的最小工程。

### 工作项

- 创建解决方案和项目。
- 配置 .NET 10。
- 配置 WPF。
- 配置依赖注入。
- 配置 CommunityToolkit.Mvvm。
- 配置 xUnit。
- 配置日志。
- 建立应用数据目录服务。
- 加入 `AGENTS.md` 和文档。

### 验收

- 应用可以启动。
- 测试项目可以运行。
- Release 构建成功。
- 主窗口使用 ViewModel，而不是把逻辑写入 code-behind。

---

## M1：音频播放纵向切片

### 目标

验证 NAudio 和最小播放状态模型。

### 工作项

- 实现 `IAudioPlayer`。
- 建立最小 `PlaybackCoordinator`。
- 建立 `PlaybackSnapshot`。
- 播放一个内置或测试 WAV/MP3。
- 支持播放、暂停、停止。
- 支持完成和失败事件。
- 展示状态。

### 验收

- 能连续播放本地测试音频。
- 暂停后继续位置正确。
- 停止后状态正确。
- 损坏文件产生可处理错误。

---

## M2：TXT 导入和章节解析

### 目标

完成小说进入系统的链路。

### 工作项

- 文件选择和拖放。
- 编码检测。
- 文本规范化。
- SHA-256 去重。
- 章节切分。
- SQLite Books/Chapters。
- 书库页。
- 章节目录。

### 验收

- 至少三本不同编码和章节格式的 TXT 导入成功。
- 无章节小说也可以导入。
- 重复文件不会重复创建。
- 导入过程不冻结 UI。

---

## M3：文本分段与播放位置

### 目标

建立稳定的朗读单元和进度模型。

### 工作项

- `ITextSegmenter`。
- 自然段和标点切分。
- 长段强制切分。
- 当前段高亮。
- 上一段、下一段。
- 进度保存和恢复。

### 验收

- 章节可生成稳定段落序列。
- 当前段落能够在 UI 中定位。
- 重启后恢复到最近段落。
- 分段测试覆盖中文标点、空行和超长段落。

---

## M4：最小 HTTP TTS

### 目标

使用最小兼容子集生成并播放在线音频，并优先确保可访问目标 HTTP TTS 后端。

### 工作项

- `HttpTtsRule`。
- 规则存储。
- 规范化运行时规则模型。
- 最小请求模板解析器。
- 必要时允许对导入规则做最小规范化，以换取后端接口兼容。
- 直接请求目标 HTTP 接口，不引入本地 Java 桥接服务或额外代理。
- `speakText` 和 `speakSpeed` 替换。
- HttpClient 请求。
- Content-Type 检查。
- 下载临时文件。
- 基础错误分类。
- 播放结果。
- 基础错误显示。

### 验收

- 至少一个目标 GET TTS 后端可成功试听；若原始规则不完全兼容，允许经最小调整后通过。
- 能朗读小说当前段。
- JSON/Text 错误不会被当成音频。
- 网络超时可取消。

---

## M5：连续播放状态机

### 目标

先稳定播放主链路，再叠加优化层。

### 工作项

- `PlaybackCoordinator`。
- `PlaybackSession`。
- 自动跨段。
- 自动跨章。
- 会话取消。
- 旧结果隔离。
- 暂停、继续、停止。
- 错误恢复。
- 连续失败保护。

### 验收

- 连续播放至少三十分钟无错乱。
- 快速切章不会播放旧音频。
- 暂停、继续和停止行为符合设计。
- 当前段失败后的恢复行为符合设计。

---

## M6：当前段缓存

### 目标

先把缓存命中和重建链路做稳。

### 工作项

- 缓存键。
- 原子写入。
- 缓存数据库。
- 缓存命中。
- 损坏缓存删除和重建。
- 残留临时文件清理。

### 验收

- 第二次播放相同段落不发起网络请求。
- 损坏缓存能够被删除和重新生成。
- 缓存文件和数据库记录保持一致。

---

## M7：常用 HTTP 规则、限流与预取

### 目标

覆盖常见规则并降低连续播放等待。

### 工作项

- POST JSON。
- POST Form。
- 自定义 Header。
- Body 模板。
- Jint 表达式。
- 基础 `java` 辅助函数。
- LoginInfo。
- 会话内 Cookie。
- 请求限流。
- 下一段和下下段预取。
- In-flight 请求去重。
- 跳章取消旧预取。
- 请求预览和规则测试。

### 验收

- 至少三个结构不同的规则工作正常。
- 跳章后旧预取不会改变当前播放。
- 401、429、5xx 和断网行为符合设计。
- 敏感 Header 在 UI 和日志中脱敏。
- 恶意或无限循环脚本受到限制。
- 缺少必需字段、非法字段值和请求模板错误有明确提示。

---

## M8：规则管理与产品化 UI

### 目标

让普通用户能够完成规则导入、测试和故障处理。

### 工作项

- JSON 对象和数组导入。
- 剪贴板导入。
- 导出。
- 编辑。
- 测试和试听。
- 直接导入校验和错误提示。
- 设置首页分组入口列表。
- 七个设置二级页：播放设置、TTS 规则、导入与文本、章节规则、缓存与数据、外观、诊断与关于。
- TTS 规则左右分栏编辑区和规则编写帮助入口。
- 章节规则左右分栏编辑区和规则编写帮助入口。
- 错误对话框或信息栏。
- 缓存与数据二级页总览和缓存管理三级页。
- LRU 清理策略完善。
- 界面细节整理。

### 验收

- 新用户无需修改配置文件即可完成主流程。
- 规则错误能定位到请求、鉴权、限流或响应问题。
- 所有主操作可从 UI 完成。
- 设置首页不再直接显示具体设置项或统一保存按钮。

---

## M9：质量、打包和发布候选

### 目标

生成可分发的第一版。

### 工作项

- 完善集成测试。
- 日志脱敏审核。
- 数据迁移测试。
- 崩溃恢复。
- 便携版或安装包。
- 第三方许可证清单。
- 用户文档。
- 已知限制。

### 验收

- Release 构建和测试通过。
- 新机器可安装或解压运行。
- 卸载不误删用户外部文件。
- 日志不含凭据和小说正文。
- 所有第三方依赖许可证已记录。
