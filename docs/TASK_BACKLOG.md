# NovelSpeaker 当前开发 Backlog

## 1. 阶段定位

上一阶段的 Wave 1–6 已全部完成，完整任务记录归档于：

- `archives/2026-07-28_COMPLETED_PRODUCT_EXPANSION_BACKLOG.md`

当前阶段只重构缓存身份、章节朗读清单和缓存完整度查询。目标是消除目录与缓存管理页在少量缓存下仍出现的明显延迟，并修复 `SegmentIndex`、朗读标题和 TTS 规则编辑导致的错误失效或错误复用。

本阶段不扩展新的内容来源、播放功能或导出格式。

## 2. 已确认边界

- 目录中的 0% 缓存进度继续不显示，这是预期 UI 行为。
- 不迁移、不兼容、不懒转换旧版音频缓存；新缓存格式上线时允许清空旧缓存索引和内部缓存文件。
- 不实现跨书籍或跨章节的全局音频去重。
- 数据库每章只持久化一份当前有效朗读清单，不保存 `TextProfile` 历史版本。
- 朗读清单不保存完整小说文本，哈希使用紧凑 BLOB，避免数据库随配置修改次数持续增长。
- 删除书籍时必须删除对应朗读清单、清单段、音频缓存索引和内部音频文件。

# Wave 7：缓存身份与持久化基础

## [x] CACHE-701（P0）：定义稳定段身份和版本化配置指纹

实现：

- 新缓存身份不再使用运行时 `SegmentIndex`。
- 正文段使用稳定来源身份，至少包含段类型、章节内来源起点和来源长度；播放顺序使用独立 `OrderIndex`。
- 章节标题使用独立的合成段类型，不插入正文段身份序列。
- 定义版本化 `TextProfileFingerprint`，只包含会影响正文分段或 `SpeechText` 的设置和规则字段。
- 定义版本化 `TtsRuleFingerprint`，使用规范化后的 URL、请求方法、Header、Body、JSON 结构标记、声明 Content-Type 和执行合同版本；不包含名称、启用状态、并发限制和时间戳。
- 定义版本化 `SynthesisProfileFingerprint`，包含 TTS 规则指纹、语速及未来会影响音频结果的扩展配置。
- `TextProfileFingerprint` 只判断朗读清单是否需要重算，不进入音频缓存键。
- 音频缓存身份至少包含 ChapterId、稳定段身份、最终 `SpeechText` 哈希和 `SynthesisProfileFingerprint`。

自动验收：

- 开关“朗读标题”不改变任何正文段缓存身份。
- 编辑规则的请求语义后指纹变化；只修改名称、并发限制或启用状态时指纹不变。
- 修改正则但最终 `SpeechText` 未变时，音频缓存身份保持不变。
- 新增未来合成配置可以通过提升指纹 schema version 接入，不修改既有身份语义。

## [x] DATA-702（P0）：新增紧凑 SQLite schema 并建立旧缓存重置边界

前置：CACHE-701。

实现：

- 追加下一版 SQLite migration，不修改已有 version 4–6 migration。
- 新增每章一条的 `ChapterSpeechPlans`。
- 新增每个当前正文段一条的 `ChapterSpeechPlanSegments`，使用复合主键和 `WITHOUT ROWID`。
- 新增小型 `SynthesisProfiles`，仅保存非敏感、规范化后的配置身份元数据。
- 重建 `AudioCacheEntries` 为新版缓存索引，使用紧凑 BLOB 哈希、整数状态和必要查询字段。
- 不保存完整 `SpeechText`、完整规则请求内容或重复章节元数据。
- `ChapterSpeechPlans.ChapterId` 外键指向 `Chapters.Id ON DELETE CASCADE`；清单段外键指向计划并级联删除。
- 音频缓存条目关联 Book/Chapter，并保证书籍删除后不存在数据库孤儿记录。
- 本 migration 是缓存格式重置边界：删除旧缓存索引，不尝试推断或迁移旧键。
- 使用受根目录约束的一次性维护步骤清理旧 `Cache/Tts` 文件；失败可重试且不影响书籍正文和阅读进度。

空间约束：

- SHA-256 等固定哈希存为 BLOB，不存十六进制 TEXT。
- 清单段不重复保存 BookId、ChapterIndex、TextProfile 或时间戳。
- 每章始终只有一份当前计划，配置变化时原位更新或事务替换。
- `SynthesisProfiles` 中无引用记录可由维护任务清理。

自动验收：

- 新库、version 6 升级、重复启动和高版本拒绝测试。
- 升级后旧音频缓存不再命中，书籍、章节、规则和阅读进度保留。
- 大量计划段的数据库体积测试，证明体积随当前段数线性增长，不随配置修改次数倍增。
- 外键级联和孤儿记录检查通过。

## [x] PLAN-703（P0）：持久化每章当前有效朗读清单

前置：CACHE-701、DATA-702。

实现：

- 章节读取、播放准备和主动缓存冻结段落时复用同一朗读清单构建用例。
- `ChapterSpeechPlans` 保存 `ChapterRevisionHash`、当前 `TextProfileFingerprint`、`PlanOutputHash`、状态和正文段数。
- `ChapterSpeechPlanSegments` 只保存顺序、稳定来源身份、段类型和最终 `SpeechTextHash`。
- 文本配置变化时先在内存生成新计划并计算 `PlanOutputHash`。
- 新旧输出完全相同，只更新计划头中的 `TextProfileFingerprint`，不重写段表。
- 输出改变时，在短事务内替换该章段记录；不保留旧 `TextProfile` 计划。
- 章节标题不写入正文计划，按当前设置动态加入完整度和播放序列。
- 当前配置计划缺失时允许返回“计算中”，由有所有者、可取消、有限并发的协调器按当前章、可视附近章节、其余章节顺序补建。

自动验收：

- 未命中正文的正则修改只更新计划指纹，不增加段记录或使音频失效。
- 部分文本变化只改变受影响段的 `SpeechTextHash`。
- 反复切换或编辑配置后，每章仍只有一条计划头和一套段记录。
- 取消、失败和进程重启不会留下半套计划。

# Wave 8：缓存写入与快速完整度查询

## [x] CACHE-704（P0）：切换到 AudioCacheKey v2 和新版索引

前置：CACHE-701、DATA-702、PLAN-703。

实现：

- 播放、预取、主动缓存和试听后的正式缓存写入统一使用 AudioCacheKey v2。
- 缓存键不包含 `SegmentIndex`、`TextProfileFingerprint` 或“朗读标题”开关。
- 正文缓存通过稳定来源身份复用；章节标题通过固定合成段类型和当前标题 `SpeechTextHash` 单独缓存。
- 缓存写入前完成格式与可解码验证，成功原子落盘后记录 `Ready` 状态。
- 缓存条目记录 `SynthesisProfileFingerprint`，避免编辑现有 TTS 规则后错误复用旧音频。
- 删除旧 v1 运行时入口和测试，不保留双查、双写或回退逻辑。

自动验收：

- 开关朗读标题、改变正文播放顺序或前置合成段时，正文缓存仍命中。
- 语速、音频相关规则内容或未来合成配置变化后不命中旧音频。
- 同章同来源范围但最终 `SpeechText` 改变时不错误复用。
- 原子写入、取消、损坏响应和并发同键合并测试通过。

## [x] QUERY-705（P0）：用 SQLite 聚合替代逐段重建和解码探测

前置：CACHE-704。

实现：

- 缓存完整度查询只读取当前章节朗读清单、当前合成配置和 `Ready` 缓存索引。
- 正常完整度查询不读取章节正文、不执行正则、不逐个 `File.Exists`、不调用音频解码器、不更新 `LastAccessedAt`。
- 使用少量批量 SQL 按章节聚合正文总数和已缓存数，并按“朗读标题”设置叠加标题段。
- 0% 仍返回给 Presentation，但目录格式化继续输出空文本。
- 计划缺失、规则不可用和无可播放内容使用明确状态，不与 0% 混淆；目录仍按既有 UI 规则决定是否显示。
- 缓存管理页可以同时显示所有历史配置音频的物理条目数/大小，以及当前配置完整度，两者统计口径明确分离。

性能预算：

- 2,000 个当前计划段的目录完整度刷新不得产生任何音频解码调用。
- 查询连接和 SQL 次数按一次批量刷新保持常数级，不随章节数逐章打开连接。
- 在固定测试环境和内存/临时 SQLite fixture 下建立可重复的性能上限或相对基线，防止退化回逐段 I/O。

## [x] PLAY-706（P0）：统一播放、预取、主动缓存和导出消费语义

前置：CACHE-704、QUERY-705。

实现：

- 当前播放和预取从同一章节内容结果取得稳定段身份，不再仅传递运行时索引。
- 主动缓存批次冻结规则、语速、文本配置和稳定段清单；命中判断使用 v2 身份。
- 主动缓存完成后提交计划/缓存变化通知，目录和缓存管理页按章节刷新。
- MP3 导出使用当前计划顺序解析缓存输入，并在导出开始时严格检查文件存在和可解码性。
- 目录完整度只作为 UI 信息，不作为导出有效性的最终证明。
- 播放命中时发现文件缺失或损坏，标记/删除索引并重新生成。

自动验收：

- 当前播放、预取、主动缓存共享同一键语义。
- 导出顺序与当前朗读计划一致，标题开关不扰动正文缓存复用。
- 目录查询信任数据库状态，但播放和导出仍能发现并修复外部删除或损坏文件。

# Wave 9：生命周期、UI 与质量收口

## [x] LIFE-707（P0）：完善书籍删除和缓存维护生命周期

前置：DATA-702、CACHE-704。

实现：

- 删除书籍 operation journal 在数据库级联前保存需要删除的内部正文和音频路径。
- 删除书籍完成后，`Books`、`Chapters`、`ReadingProgress`、`ChapterSpeechPlans`、`ChapterSpeechPlanSegments` 和 `AudioCacheEntries` 不得存在相关记录。
- 文件删除只允许作用于应用数据根目录；失败保留可恢复 journal，启动恢复可继续执行。
- 增加渐进式缓存健康维护：检查缺失文件、按需/低优先级验证长期未使用条目并修正状态。
- 正常页面查询不承担健康扫描责任。
- 清理音频缓存不删除书籍、章节、阅读进度或当前朗读清单。

自动验收：

- 删除有大量计划和缓存的书籍后，数据库与文件系统均无对应残留。
- 删除中断后的启动恢复测试。
- 非法路径、reparse point 和应用根目录逃逸测试。
- 缓存健康维护发现缺失/损坏文件后发布章节变化通知。

## [x] UI-708（P1）：接入快速完整度状态和刷新语义

前置：QUERY-705、PLAY-706。

实现：

- 播放页目录和书籍详情目录继续遵循：0%、不可用、无可播放段或计算中时不显示百分比。
- 1%–100% 使用现有整数百分比格式，不调整既有用户预期。
- 缓存管理页显示“当前配置完整度”，并在计划计算中、不可用和无可播放内容时使用明确文案。
- 缓存管理页订阅缓存/计划变化通知，使后台主动缓存和计划补建后无需重新进入页面即可更新。
- 连续章节通知合并刷新，页面离开时取消查询并退订。

自动验收：

- 目录 0% 继续为空文本的回归测试。
- 计划计算中到完成、主动缓存写入、缓存清理和损坏修复后的刷新测试。
- 页面重复进入/离开无重复订阅和迟到更新。
