# 2026-08-03 放弃的全局视觉 Wave 1

> 本文只用于历史追溯。该实现从提交 `e8079000d4bd82f844e7741fb35cc6e63ad17e2f` 开始，基线父提交为 `25a746c608bd46f87126b828b6c879104f3c08c6`。最终代码通过单个 `git revert --no-commit` 聚合提交回到基线行为，当前实现依据为数字编号文档和 `../TASK_BACKLOG.md`。

## 1. 原目标

该阶段试图一次建立语义颜色、Design Token、公共按钮、媒体控件、输入、列表、卡片、导航、页面密度和页面布局，并把大多数页面迁移到公共资源。

## 2. 放弃原因

- 颜色体系、公共样式、控件模板、页面密度和页面布局同时变化，影响范围无法隔离。
- Application/global 作用域的标准控件隐式样式与 Wpf.Ui provider 争夺类型资源键。
- 部分公共样式未稳定继承 Wpf.Ui 默认模板和交互状态。
- 主题切换后需要运行时代码重新恢复输入控件 Style，说明资源所有权依赖加载顺序和补丁逻辑。
- Shell、NavigationView、页面和组件同时设置边距、宽度和对齐，造成重复空白、零宽度编辑器和窗口尺寸相关漂移。
- 初始测试偏重资源键存在性，不能阻止真实测量、内容对齐和模板状态异常。
- 后续修复虽然恢复部分 `BasedOn`、对齐和几何合同，但仍建立在不稳定的全局覆盖边界上。

## 3. 可保留的经验

- 语义颜色、Accent 使用范围和柔和表面层级仍是最终视觉目标。
- WPF 测试需要覆盖真实资源解析、测量、Focus、Disabled、主题切换和窗口最小尺寸。
- 页面几何只能测试可用下限，不能把未确认的精确 Padding/Width 固化为合同。
- 视觉开发需要小范围任务、独立 Style Gallery、自动截图和可回退提交。
- Wpf.Ui 标准模板、NovelSpeaker 主题资源、自有组件和页面布局必须有明确所有权。

## 4. 后续边界

新的视觉体系不沿用该阶段的全局隐式标准控件样式、运行时 Style 恢复和一次性页面迁移。新实现从回退后的实验分支逐步建立，每个编号任务均可自动执行和自动验收，并默认在完成一个任务后停止。
