# 正则替换管线

## 1. 文档定位

本文定义 NovelSpeaker 当前主线中的 **正则替换** 功能。该功能统一使用“正则替换”命名，不再使用“文本清理规则”。

正则替换已经进入主线任务，具体实施任务见 `11_TASK_BACKLOG.md` 的 **Epic AB：正则替换**。

---

## 2. 当前主线范围

正则替换用于在不重新导入书籍的前提下，对已导入小说的运行时段落进行动态处理。

当前主线必须支持：

- 全局规则：所有书籍共用同一套启用规则。
- 新建、编辑、启用、禁用、排序和删除规则。
- 分别作用于展示文本、语音文本或两者。
- 多条启用规则按稳定顺序组合执行。
- 修改规则后立即重建当前章节的运行时段落。
- 语音文本改变后，从当前段开头重新建立播放会话，并保持修改前的播放或暂停状态。
- 正则校验、执行超时和错误状态展示。

当前主线不提供：

- 单本书专属规则。
- 规则导入、导出或内置默认规则。
- 替换预览或示例文本输入。
- 用户可配置的正则选项。
- 通过正则替换重新划分、合并或识别章节。
- 规则市场或插件系统。

---

## 3. 在文本链路中的位置

正则替换在动态分段完成后逐段执行，不能改变段落边界：

```text
Books/<book-id>/content.txt
  ↓
按 Chapter.StartOffset / Length 读取原始章节文本
  ↓
动态段落切分，保留原始 StartOffset / Length
  ↓
对每个段落应用全局启用的正则替换规则
  ├─ 生成 DisplayText
  └─ 生成 SpeechText
  ↓
过滤空结果并建立运行时段落列表
  ↓
消费内容
  ├─ UI 展示正文
  └─ 构建 TTS 请求和位置相关音频缓存键
```

要求：

- `StartOffset` 和 `Length` 始终指向原始规范化正文。
- 正则替换只改变运行时产生的 `DisplayText` 和 `SpeechText`。
- 修改规则不改写 `content.txt`，也不改写章节偏移。
- 进度恢复仍优先使用原始字符偏移，不能只依赖可能变化的运行时段落索引。
- 正则替换不能在执行后重新分段，也不能跨段合并文本。

## 4. 规则模型

建议使用以下领域模型：

```csharp
public enum RegexReplacementScope
{
    Display,
    Speech,
    Both
}

public sealed record RegexReplacementRule(
    Guid Id,
    string Name,
    bool IsEnabled,
    int SortOrder,
    string Pattern,
    string Replacement,
    RegexReplacementScope Scope,
    DateTimeOffset CreatedAt,
    DateTimeOffset UpdatedAt);
```

字段说明：

- `Id`：稳定规则标识。
- `Name`：用户可见名称。
- `IsEnabled`：是否参与运行时处理。
- `SortOrder`：执行顺序，值越小越先执行。
- `Pattern`：正则表达式。
- `Replacement`：.NET 正则替换文本，允许 `$1`、`${name}` 等标准引用。
- `Scope`：`Display`、`Speech` 或 `Both`。

当前主线不保存 `RegexOptions` 字段，也不在 UI 提供忽略大小写、多行或单行模式开关。所有规则统一使用固定配置：

```csharp
RegexOptions.CultureInvariant
```

每条规则、每个段落的执行超时固定为：

```text
100 ms
```

## 5. 执行规则

### 5.1 执行顺序

启用规则按以下顺序执行：

```text
SortOrder 升序
  → Id 作为稳定次序兜底
```

对每个原始段落分别生成两条处理链：

```text
rawSegmentText
  ↓
Scope = Display 或 Both 的启用规则
  ↓
DisplayText

rawSegmentText
  ↓
Scope = Speech 或 Both 的启用规则
  ↓
SpeechText
```

规则：

- 禁用规则不参与执行。
- 每条规则使用上一条规则的输出作为输入。
- 展示范围规则不影响语音文本。
- 语音范围规则不影响展示文本。
- `Both` 在两条链中分别执行，不能先处理一次再共享结果，否则不同作用范围的前序规则可能产生错误顺序。

### 5.2 空结果

替换结果为空时：

- `SpeechText` 为空：该段不提交 TTS，并在播放推进时自动跳过语音消费。
- `DisplayText` 为空：该段不出现在正文预览列表中。
- 两者都为空：该段从运行时消费列表中完全跳过。
- 原始 `StartOffset` 和 `Length` 仍保留在处理结果或映射信息中，用于进度恢复和跳转映射。

实现时必须避免因连续多个空语音段造成递归推进、无限循环或段落索引越界。

### 5.3 正则错误和超时

- Pattern 在保存前必须编译校验；无效 Pattern 不允许保存。
- 运行时必须再次捕获 `ArgumentException` 和 `RegexMatchTimeoutException`，不能信任数据库中的历史数据始终有效。
- 单条规则在单个段落执行超过 `100 ms` 时，本次处理跳过该规则，并继续执行其后的规则。
- 超时或运行时错误不能中断章节加载或播放链路。
- 出错规则保持启用，不自动修改用户配置，但规则列表和编辑区应显示错误状态。
- 错误信息不得包含完整小说正文，只显示规则名称、错误类型和安全的简短说明。

## 6. 当前章节刷新与播放语义

规则发生以下变化后，需要立即刷新当前章节：

- 新建并保存规则。
- 修改名称以外的执行字段：Pattern、Replacement、Scope。
- 启用或禁用规则。
- 调整规则顺序。
- 删除规则。

刷新流程：

```text
记录当前书籍、章节、原始字符位置和播放/暂停状态
  ↓
取消旧的章节重建任务，并使用最新规则生成新的运行时段落
  ↓
根据原始字符偏移映射到新的当前段
  ↓
取消受影响章节的旧预取，避免旧 SpeechText 音频晚到
  ↓
比较当前映射段的新旧 SpeechText
  ├─ 未变化：保留当前音频播放位置，仅刷新正文与后续队列
  └─ 已变化或当前段被过滤：停止当前音频，从映射后的当前段开头重建播放会话
  ↓
修改前正在播放：保持播放
修改前处于暂停：保持暂停
```

补充要求：

- 仅修改规则名称不会影响处理结果，不要求重建当前章节。
- 刷新期间 UI 应显示轻量加载状态，旧异步结果不得覆盖新规则生成的章节。
- 仅 DisplayText 发生变化时，不应无故中断当前音频。
- 后续段 SpeechText 变化时取消对应旧预取，但不要求打断当前未变化的音频。
- 如果当前原始段被规则完全过滤，应定位到最近的后续可消费段；没有后续段时回退到前一可消费段。
- 规则变更不得触发重新导入或章节重建。

## 7. 音频缓存键策略

当前实现保持位置相关缓存键，不改为跨书籍、跨章节的内容寻址缓存。

缓存键继续由 `AudioCacheKey.FromPlayback` 的以下字段构成：

```text
SHA256(
  bookId
  + chapterIndex
  + segmentIndex
  + ruleId
  + speakSpeed
  + finalSpeechText
)
```

并由 `AudioCacheKey.CurrentVersion` 提供版本命名空间。

要求：

- `finalSpeechText` 必须是全部语音范围规则执行后的最终 `SpeechText`。
- 语音文本变化会产生新缓存键。
- 只改变 `DisplayText` 不会改变同一位置的缓存键。
- 不把正则规则配置哈希加入缓存键。
- 即使不同书籍或不同段落产生相同 `SpeechText`，也不跨位置复用缓存。
- 旧缓存不立即删除，交由现有 LRU 和按书籍/章节清理逻辑处理。

该策略优先保持当前缓存统计、章节完整度和按书籍清理语义，不在本 Epic 中引入内容寻址缓存重构。

## 8. 持久化

规则保存在 SQLite 的 `RegexReplacementRules` 表中。当前只支持全局规则，因此不增加 `BookId`。

建议字段：

```text
Id TEXT PRIMARY KEY
Name TEXT NOT NULL
IsEnabled INTEGER NOT NULL
SortOrder INTEGER NOT NULL
Pattern TEXT NOT NULL
Replacement TEXT NOT NULL
Scope TEXT NOT NULL        -- Display / Speech / Both
CreatedAt TEXT NOT NULL
UpdatedAt TEXT NOT NULL
```

持久化要求：

- `SortOrder` 必须形成稳定顺序。
- 启用状态和排序使用独立字段更新，不能被右侧旧编辑副本覆盖。
- 删除规则后重新整理排序值。
- 数据库迁移必须兼容已有用户数据。
- 读取到非法 Scope 或 Pattern 时不得使应用启动失败，应隔离该规则并显示错误。

## 9. UI 入口与交互

入口固定为：

```text
设置 → 导入与文本 → 正则替换
```

“正则替换”是三级规则管理页，采用左侧列表、右侧编辑区的工作台布局。

### 9.1 左侧规则列表

提供：

- 选择规则。
- 启用或禁用，操作后即时保存。
- 拖动排序，以及无边框上移/下移图标按钮，操作后即时保存。
- 错误状态标识。
- 新建规则入口。

不提供：

- 导入。
- 导出。
- 默认规则。
- 单本书范围选择。

### 9.2 右侧编辑区

字段：

- 名称。
- 正则表达式。
- 替换文本。
- 作用范围：展示、语音、两者。
- 正则校验和运行时错误提示。
- 删除、取消、保存。

不显示：

- 启用开关。
- 排序字段。
- 正则选项。
- 替换预览或示例文本。

### 9.3 保存策略

- 左侧启用/禁用和排序即时保存。
- 右侧名称、Pattern、Replacement 和 Scope 使用保存/取消。
- 右侧保存必须基于最新持久化对象做字段级更新，不能覆盖左侧已经保存的启用状态或排序。
- 切换规则、返回、新建或删除前存在未保存修改时，显示保存、放弃、取消。
- 删除必须二次确认。
- 保存成功后按第 6 节规则刷新当前章节。

## 10. 与章节规则的边界

章节规则只负责识别章节标题和章节范围。

正则替换只负责动态分段完成后的展示和语音文本替换。

二者不能混合：

- 不用章节规则做广告过滤、符号替换或朗读规范化。
- 不用正则替换重新划分章节或合并段落。
- 修改正则替换规则不触发章节重建。
- 修改章节规则或重新解析章节才会影响章节边界。

## 11. 测试要求

至少覆盖：

### 模型与持久化

- 新建、读取、字段级更新、删除和稳定排序。
- 左侧启用/排序不会被右侧编辑副本覆盖。
- 非法 Scope 和历史非法 Pattern 被隔离。

### 执行管线

- Display、Speech、Both 分别生效。
- 多条规则按稳定顺序组合。
- 禁用规则不生效。
- 固定使用 `CultureInvariant`，UI 不暴露 RegexOptions。
- 无效 Pattern 不允许保存。
- `100 ms` 超时被捕获并跳过当前规则。
- 规则异常不导致章节加载或播放崩溃。

### 空结果与进度

- 空 `DisplayText` 不显示。
- 空 `SpeechText` 不发起 TTS。
- 两者都为空时完全跳过。
- 连续空段可以稳定推进。
- 规则改变后根据原始字符偏移恢复到最近段落。

### 播放和缓存

- 保存执行字段后立即重建当前章节。
- 当前映射段 SpeechText 变化或被过滤时，从映射后的当前段开头重建播放；只改变 DisplayText 时当前音频不中断。
- 修改前播放中则保持播放，修改前暂停中则保持暂停。
- 语音文本变化形成新的位置相关缓存键。
- 只改变展示文本不改变同一位置的缓存键。
- 相同文本位于不同书籍或段落时不跨位置复用缓存。

### UI

- 左侧启用和排序即时保存。
- 右侧保存/取消与未保存修改保护。
- 页面不出现预览、导入、导出、默认规则和正则选项。
- 错误状态可被键盘和屏幕阅读器识别。
